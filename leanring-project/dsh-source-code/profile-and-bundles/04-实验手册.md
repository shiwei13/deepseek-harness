# 04：用三个实验验证 Profile 组合

实验代码位于 [`leanring-project/profile-demos`](../../profile-demos/)。每个实验都从仓库根目录执行，并使用当前 checkout 中的真实 `dsh-app-boot` 与 Include 源码。

## 准备

```sh
pnpm install
```

如果只运行一项实验，直接执行对应命令；也可以用 `node --import tsx/esm leanring-project/profile-demos/run-all.ts` 依次运行全部实验。

## 实验一：逐层观察 config 整段替换

```sh
node --import tsx/esm leanring-project/profile-demos/01-layer-order/run.ts
```

程序依次应用 base bundle、feature bundle、profile、home 和 `--patch` 五层。每一层都替换同一个 `learning-observer` 的 `config`，输出会显示上一层的专属键立即消失，最后只剩 overlay 写入的字段。

读代码时重点看 [`01-layer-order/run.ts`](../../profile-demos/01-layer-order/run.ts) 如何把层交给 `composeEntries()`。然后把最后一层删掉重跑，验证 home 层成为最终值。

## 实验二：验证两种 manifest 与双锚点解析

```sh
node --import tsx/esm leanring-project/profile-demos/02-profile-resolution/run.ts
```

程序创建一个临时 dsh 安装锚点和一个临时 Harness home，把 `dsh-learning-base` 放在安装侧，把 `dsh-learning-feature` 放在 profile 侧，再调用真实 `loadProfile()`。输出先列出每个 bundle 的解析目录，再打印 profile 用户层覆盖后的最终行。

对照阅读 [`fixtures/profile/package.json`](../../profile-demos/fixtures/profile/package.json) 与两个 bundle 的 `package.json`。可以把 profile 的 bundles 顺序对调重跑，观察 feature 层因为目标 id 尚未被 base 插入而产生警告。

## 实验三：运行真实 CLI 的 dump 与启动路径

```sh
node --import tsx/esm leanring-project/profile-demos/03-real-dsh/run.ts
```

程序在系统临时目录组装一个隔离 profile，设置子进程自己的 `DSH_HOME`，先执行真实的 `dsh --profile learning --dump-config --patch ...`，再执行同一 profile 的正常启动。最终插件会打印自己实际收到的 config 并请求启动器有界退出。

dump 输出的一条 `# ==` 注释会按顺序列出原始 base bundle，以及后来修改该行的 feature bundle、profile patch、home patch 和命令行 overlay。正常启动只打印 overlay 的 config，且 base、feature、profile 与 home 各自独有的键都不存在，这同时验证了层优先级与整段替换。

实验用 `finally` 删除自己创建的临时 Harness home，不会触碰真实 `~/.dsh`。如果你想保留现场检查目录，可临时注释 [`03-real-dsh/run.ts`](../../profile-demos/03-real-dsh/run.ts) 末尾的清理语句；不要把生成的 `node_modules` 或 home 内容提交进仓库。

## 建议的破坏性练习

这些修改只针对 demo fixture，失败后可直接恢复文件：

1. 从 feature bundle 的 `package.json` 删除 `dsh.bundle`，观察 `loadProfile()` 如何明确拒绝它。
2. 把 profile patch 的 `learning-observer` 改成不存在的 id，比较 stderr 警告与最终配置。
3. 把任意 patch 文件清空，再与写入 `[]` 的结果比较。
4. 在 patch 上加上错误的 `name`，观察 name mismatch 保护。
5. 删除 overlay 中的 `config.overlayOnly`，确认 `config` 中不会自动找回 home 层的字段。

完成这些实验后，再回到真实组合包 [`dsh-base`](../../../packages/bundle/base/cordis.patch.yml)、[`dsh-web-app`](../../../packages/bundle/web-app/cordis.patch.yml) 与 [`dsh-headless`](../../../packages/bundle/headless/cordis.patch.yml)，按 id 搜索同一行在不同层的定义，就能把大配置拆成可理解的增量。
